# 报喜管理「官方随份子」列三态化设计

日期：2026-11-15
状态：已确认（用户确认：按结婚证判定，状态文字统一用「结婚证」）

## 意图

报喜信息管理列表的「官方随份子」列，由现在的「已随 ¥金额 / -」两态改为三态展示，
让管理员一眼看出：谁还没传结婚证、谁传了但还没随份子、谁已经随了。

## 目标 / 非目标

- 目标：列渲染三态 Tag（灰/蓝/绿）；列宽 110 → 170；Tag 带 title 悬停完整文字。
- 非目标：不改接口、不加筛选条件、不动详情弹窗与其它列。

## 约束

- 判定字段（列表接口现成）：`has_marriage_certificate`（是否已有结婚证）、
  `is_official_gift`、`gift_amount`（分）。
- 金额显示：`已随￥{formatCents(gift_amount)}`——全角￥、两位小数（`formatCents` 现成，输出 "520.00"）。
- Tag 需带 `title` 属性（项目表格规范）。
- 消息提示/枚举等其它规范不涉及（纯展示逻辑，无新增枚举、无新接口）。

## 方案选择

- **选定**：前端列渲染直接按两字段派生三态（唯一可行方案——列表接口已含所需字段，无需后端改动）。
- 备选（按报喜照片 photos 判定）：不采用——photos 提交必填，不存在「未上传」状态；且列表接口无 photos 标记（用户已确认按结婚证）。

## 三态判定与文案（已确认）

| 状态 | 判定 | 展示 |
|------|------|------|
| 未上传结婚证 | `has_marriage_certificate !== true` | 灰 Tag「未上传结婚证」 |
| 已传结婚证，未随份子 | `has_marriage_certificate && !is_official_gift` | 蓝 Tag「已传结婚证，未随份子」 |
| 已随份子 | `is_official_gift` | 绿 Tag「已随￥{金额}」 |

## 留给实现者

- 三态判定提取为小组件/纯函数（可单测）；Tag 颜色选 antd 预设色。
- 测试：三态各一例 + 金额格式一例（TDD，80% 覆盖口径按项目惯例）。
