# 报喜已通过后独立设置官方随份子 设计

日期：2026-11-15
状态：已确认（用户确认：已审核通过的报喜可独立设置官方随份子状态）

## 意图

报喜审核通过后，若当时未设置官方随份子，管理员可在详情弹窗独立补设置，
调用现成接口 `PUT /admin/v1/bizops/congratulation/{id}/gift`（summary「设置官方随份子」）。

## 目标 / 非目标

- 目标：详情弹窗新增「官方随份子」独立区块（仅已通过状态显示）；设置成功后刷新列表并关闭弹窗。
- 非目标：不做取消/修改随份子（后端「提交后不可变更」）；不改列表页；不动审核主流程（已提交/未通过的设置仍走审核勾选）。

## 约束

- 接口：`congratulationApi.setGift(id, { is_official_gift: true, gift_amount: 分 })`（service 现成）。
- 状态枚举用 `CongratulationStatus.APPROVED`（@shared/constants，禁止硬编码）。
- 弹窗 `maskClosable={false}`（ScrollableModal 已内置）；消息提示 `useAppNotification`。
- 金额元输入（`InputNumber` min 0.01 precision 2），提交时 `Math.round(元*100)` 转分。

## 方案选择

- **选定**：详情弹窗内新增独立区块——入口沿用现有列表「详情」按钮，改动最小，且与审核区同屏可见。
- 备选（列表行内设置按钮）：不采用——设置动作低频、需填金额，弹窗区块更合适。

## 区块逻辑（已确认）

| 状态 | 展示 |
|------|------|
| 已通过 且 未设置 | 勾选框「官方随份子」+ 金额输入（元）+「设置随份子」按钮 |
| 已通过 且 已设置 | 只读：已设置 ¥xx.xx，一经提交不可变更 |
| 已提交 / 未通过 | 不显示该区块 |

- 提交校验：未勾选不提交（按钮点击时校验勾选）；勾选后金额必填且 >0。
- 成功后：toast「官方随份子已设置」+ `onSuccess()` 刷新列表 + 关闭弹窗（与审核流程一致）。
- 审核区随份子勾选在**已通过**状态下隐藏（避免同一设置双入口）；已提交/未通过照旧。
