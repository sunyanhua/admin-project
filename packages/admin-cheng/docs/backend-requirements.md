# 后端功能补充说明与新增需求

> 本文档基于 `docs/demo-guide.md` 和 `docs/frontend-miniapp-guide.md` 原始需求，整理 DEMO 制作过程中新增的功能设计与交互逻辑，发回管理后台和后端开发团队参考。

---

## 一、报名/购买流程模式

原始设计仅有一种流程：用户在详情页选择 SKU → 填写信息 → 支付下单。DEMO 中扩展为 **四种模式**：

### 模式 1：先登记后支付（原有，适用于需要预先收集信息的场景）

**示例**：2025大运河音乐节

```
选择票种 → 选择日期 → 选择数量 → 优惠券 
  → 下一步 → 填写报名信息 → 勾选协议 → 确认并支付
```

- 支付前必须完成信息登记
- 支付后订单中即包含完整的人员信息

### 模式 2：先支付后登记（新增，适用于快速下单场景）

**示例**：2026冰丝带汽车生活节

```
选择票种 → 选择日期 → 选择数量 → 优惠券 
  → 勾选协议 → 确认并支付
```

- Step 1 中需展示"我已阅读并同意 XXX 协议"的勾选框
- 支付时跳过信息填写，直接生成订单
- 订单生成时 `persons` 字段为空模板（标注需填写的标签如"成人×2、儿童×1"）
- 支付后进入订单详情，每张入场券卡片显示"请登记报名信息后核销使用"提示 + "登记"按钮
- 点击"登记"弹出登记表单，填写后入场券卡片变为人员信息 + "核销"按钮

### 模式 3：先支付后预约+登记（新增，适用于需要预约时段的票务）

**示例**：什刹海摇橹船票

```
选择船票类型 → 选择数量 → 优惠券 
  → 勾选协议 → 确认并支付
```

- 支付时跳过信息填写
- 订单中每张门票卡片显示"请先预约使用时间后核销使用"提示 + "预约"按钮
- 点击"预约"弹出日历界面：
  - 月视图日历（支持切换月份），选择日期
  - 每日展示多个时段（如 09:00-10:00、10:00-11:00 等），标注"可预约"/"不可预约"
  - 选择日期+时段后出现购票人信息表单
  - 确认预约按钮上方红字提示："⚠ 预约完成后不能修改，且本订单不再退款"
- 预约完成后卡片变为人员信息 + 预约时间 + "核销"按钮
- 预约完成后不可再退款

### 模式 4：无需登记（新增，适用于极简购买场景）

**示例**：景山公园门票

```
选择票种 → 选择数量 → 优惠券 
  → 勾选协议 → 确认并支付
```

- 支付后订单卡片直接显示产品名称和票种，仅保留"核销"按钮
- 无登记、无预约流程

### 后端字段建议

Product 表需新增字段标识报名模式：

| 字段 | 类型 | 说明 |
|------|------|------|
| `register_mode` | enum | `pre`（先登记后支付）/ `post`（先支付后登记）/ `none`（无需登记） |
| `need_booking` | boolean | 是否需要预约（票务类可用） |
| `booking_time_slots` | json | 可预约时段配置，如 `["09:00-10:00","10:00-11:00",...]` |

## 二、订单结构与卡券管理

### 订单与卡券的关系

原始设计中订单仅记录"买了什么，多少钱"。DEMO 中将一个订单的购买份数（quantity）拆分为多张独立卡券：

- 用户购买"双人票 × 2"，订单包含 **2 张入场券**，每张有自己的人员信息、核销状态、转赠状态
- 每张卡券在订单中横向滑动展示，使用票券样式卡片
- 卡券在"我的票夹"中也单独管理

### persons 数据结构扩展

```json
{
  "persons": [
    {
      "group": 1,           // 卡券编号（第几张）
      "label": "成人1",      // 人员标签
      "name": "张三",       // 姓名（后登记模式初始为空）
      "mobile": "138...",
      "idcard": "110101..."
    },
    {
      "group": 1,
      "label": "成人2",
      "name": "",
      "mobile": "",
      "idcard": ""
    }
  ],
  "quantity": 2,            // 购买份数（= 卡券张数）
  "person_count": 2,        // 每份卡券需要登记的人数
  "person_labels": ["成人1","成人2"],
  "registered": { "1": true, "2": false }  // 各卡券登记状态
}
```

### 订单状态

| 状态 | 说明 | 前端展示 |
|------|------|------|
| `pending` | 待付款 | 状态=待付款，按钮=马上支付 |
| `paid` | 已付款 | 状态=已支付，按钮=申请退款 |
| `refunded` | 已退款 | 状态=已退款，所有卡券灰化，仅有灰色"已退款"标记 |

订单状态数据结构：

| 字段 | 类型 | 说明 |
|------|------|------|
| `status` | enum | `pending` / `paid` / `refunded` |
| `verified` | object | 每张卡券核销状态，如 `{"1":true,"2":false}` |
| `transferred` | object | 每张卡券转赠状态 |
| `bookings` | array | 预约记录列表（预约模式用） |

## 三、票夹功能（新增）

### 概述

"我的票夹"（`my-tickets.html`）将用户购买的所有入场券和门票集中管理，与订单详情页功能一致，但独立成页便于日常使用。

### 功能

- 按"全部 / 活动入场券 / 门票"三个 Tab 切换筛选中
- 每张票卡显示关联的产品名称（可点击进入活动页）和票种
- 右下角"查看订单"链接跳转订单详情
- 支持核销、转赠、登记、预约等全量操作（与订单详情一致）
- 已使用/已转赠的票卡灰色显示
- 他人转赠的票卡显示"来自他人转赠"且不可再次转赠

### 特殊票卡类型

| 类型 | 来源 | 显示 | 操作 |
|------|------|------|------|
| 正常购买 | 用户自己下单 | 正常彩色 | 全部可用 |
| 已转赠 | 用户转出 | 灰色+50% | 无操作 |
| 已核销 | 已使用 | 灰色+50% | 无操作 |
| 已退款 | 已退款 | 灰色+50% | 无操作 |
| 他人转赠 | 他人转给自己 | 正常彩色 | 核销/登记/预约可用，不可再次转赠 |

### 后端建议

票夹数据可通过用户订单列表接口获取，无需单独接口。但需支持：

- 查询用户所有活动+票务类订单（`type: event | ticket`）
- 展开订单中每张卡券信息（含核销/转赠/登记状态）
- 支持"他人转赠"类型，即标记 `is_received: true`，不关联原下单用户

## 四、核销与转赠

### 核销

| 项目 | 说明 |
|------|------|
| 触发 | 点击卡券上的"核销"按钮 |
| 弹窗 | 居中弹窗，标题"核销"，二维码（placeholder），提示文字，琥珀色警告 |
| 完成后 | 卡券变灰，按钮灰显"已核销"，转赠按钮同时隐藏 |
| 批量 | 支持批量核销（多条选中→统一弹出二维码→关闭后全部标记已核销） |
| 退款 | 任一卡券已核销后不可退款 |

转赠完成后再进行核销时：
- 核销按钮隐藏（因已转赠）

### 转赠（新增）

| 项目 | 说明 |
|------|------|
| 触发 | 点击卡券上的"转赠"按钮（粉色，与核销金色区分） |
| 弹窗 | 居中弹窗，标题"转赠"，二维码（placeholder），提示"请将本二维码向您要转赠的亲友出示"，红色警告"请不要向其他人出示以避免被误领"，琥珀色警告"⚠ 转赠后无法收回，且本订单不能退款" |
| 完成后 | 卡券变灰，转赠按钮灰显"已转赠"，核销/登记/预约按钮全部隐藏 |
| 限制 | 1) 已核销的卡券不可转赠；2) 转赠后的卡券不可核销；3) 他人转赠的卡券不可再次转赠；4) 任一卡券转赠后订单不可退款 |
| 未登记时 | 转赠按钮可用，转赠后登记按钮也隐藏 |

### 后端建议

收赠方扫码后的处理逻辑：
- 转出方生成转赠二维码（含卡券唯一标识）
- 接收方扫码后在"我的票夹"出现该卡券，标记为 `is_received: true`
- 接收方可正常使用（核销、登记），但不可再转赠
- 转赠接口需记录转赠时间和双方用户 ID

## 五、预约模式（新增）

### 概述

适用于"什刹海摇橹船票"等需要用户提前预约使用时间的票务产品。

### 预约弹窗

```
┌─ 选择预约时间 ──────────────────────┐
│ ⚠ 预约完成后不能修改，且本订单不再退款 │
├─ 选择日期 ──────────────────────────┤
│  ◀ 8月 2026年 ▶                     │
│  日 一 二 三 四 五 六                │
│  ...日历网格...                      │
├─ 选择时段 ──────────────────────────┤
│  [09:00-10:00] [10:00-11:00] ...     │
├─ 购票信息 ──────────────────────────┤
│  购票人                              │
│  姓名 [___] 手机号 [___]             │
├─ [确认预约]                           │
└──────────────────────────────────────┘
```

### 逻辑

- 日期选择：月视图日历，支持切换月份，已过日期灰显不可选
- 时段：每日多个时段，后台管理可配时段和各时段容量
- 后登记模式的票务在预约时同时填写购票人信息
- 确认预约后不可退款
- 支持批量预约（多张票选同一时段）

### 后端建议

Product 表新增 `booking_config` 字段：

```json
{
  "enabled": true,
  "advance_days": 14,               // 可预约未来天数
  "time_slots": [
    {"slot": "09:00-10:00", "capacity": 20},
    {"slot": "10:00-11:00", "capacity": 20}
  ]
}
```

订单 bookings 结构：

```json
{
  "bookings": [
    {
      "group": 1,                   // 卡券编号
      "date": "2026-08-05",         // 预约日期
      "slot": "10:00-11:00",        // 预约时段
      "status": "booked"            // booked / cancelled / used
    }
  ]
}
```

## 七、订单数据传递

### 当前 DEMO 方案

下单时构建完整 order JSON 对象，通过 `localStorage.setItem('lastOrder', JSON.stringify(order))` 存入，订单详情页读取并渲染。

### 后端建议

下单接口返回的订单对象应包含以下完整字段（超出原始设计）：

| 字段 | 在原始设计中 | 说明 |
|------|:---:|------|
| `quantity` | 有 | 购买份数 |
| `persons` | 有 | 人员信息（需扩展 group, label 等） |
| `person_labels` | **新增** | 展示用标签如 ["成人1","成人2","儿童"] |
| `person_count` | **新增** | 每张卡券登记人数 |
| `register_mode` | **新增** | pre / post / none |
| `registered` | **新增** | 各卡券登记状态 |
| `verified` | **新增** | 各卡券核销状态 |
| `transferred` | **新增** | 各卡券转赠状态 |
| `bookings` | **新增** | 预约记录 |
| `status` | 有 | 扩展为 pending / paid / refunded |
| `cover_image` | 有 | 产品封面图（订单列表展示用） |
| `express_company` | **新增** | 快递公司 |
| `express_no` | **新增** | 快递单号 |
| `refund_stages` | 有 | 退款阶段规则 |
| `is_booking` | **新增** | 是否为预约模式产品 |
| `is_no_register` | **新增** | 是否无需登记 |
| `is_received` | **新增** | 是否来自他人转赠 |
| `detail_url` | **新增** | 关联的产品详情页链接 |

## 八、列表与筛选

### 活动/门票/商品列表

三个列表页结构统一，每页均有：
- 搜索框（半透明样式，深色背景上）
- 分类筛选胶囊标签（如汽车/户外/亲子/音乐）
- 列表卡片统一布局（封面图 + 标题 + 辅助信息 + 价格"元起"）

### 我的订单列表（`my-orders.html`）

- 四个 Tab 切换：全部 / 待付款 / 已付款 / 已退款
- 每项展示封面图、产品名称、购买明细、状态、金额
- 点击进入订单详情页
